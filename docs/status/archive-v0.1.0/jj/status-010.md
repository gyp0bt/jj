| 優先度 | ドメイン | 実装状況 | 説明 |

## 次の担当者へ

### 実装優先度（Phase 1: 基盤整備）

以下の順で実装を進めてください:

1. **設定管理層の統合**
   - `vocab.yaml`, `extensions.yaml`, `prefixes.yaml` の読込実装
   - Pydanticモデルの定義
   - `.j2/config/` の初期化処理
   - 参照: `docs/specs/03-config.md`

2. **runコマンド層のproperties抽出拡張**
   - コメント記法（`# props start` - `# props end`）の実装
   - `sys.argv` 解析と変数名の対応付け
   - Bash変数（`$1`, `$2`）の解析
   - 参照: `docs/specs/04-run-command.md#5-properties抽出`

3. **runコマンド層のファイル差分検出**
   - 実行前後のスナップショット機能
   - 差分検出ロジック
   - `Relation(label=generated)` の自動生成
   - 参照: `docs/specs/04-run-command.md#6-ファイル差分検出`

4. **コアデータモデル層の拡張**
   - グラフマージ機能
   - ノード/関係の更新・削除機能
   - トランザクション管理
   - 参照: `docs/specs/01-core-data-model.md#4-実装計画`

### 設計上の懸念事項

1. **properties抽出の複雑性**
   - スクリプト内のコメント記法とコマンドライン引数の対応付けが複雑。
   - 複数言語（Python, Bash, Perl等）への対応方針を要検討。
   - → `docs/specs/04-run-command.md#5-properties抽出` に詳細を記載。

2. **ファイル差分検出のパフォーマンス**
   - 大量ファイル（10,000件以上）でのスナップショット取得が遅延する可能性。
   - 並列処理やキャッシュの導入を検討。
   - → `docs/specs/04-run-command.md#6-ファイル差分検出` に方針を記載。

3. **設定管理の初期化タイミング**
   - `.j2/config/` の自動生成タイミング（初回実行時 or `jj init`）を要検討。
   - デフォルト設定の埋め込み方針。
   - → `docs/specs/03-config.md#4-初期化とデフォルト設定` に方針を記載。
